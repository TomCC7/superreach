# Evaluation protocol

The published browser policy is `e6-submm@20k`. Its [native MuJoCo evaluation](evaluation-data/e6-submm-20k-native.json) contains 129 case/mode runs: 39 each for clean, noisy with 10 ms delay, and full hardware domain randomization; six for MOVE–HOLD–MOVE; and three each for payload jump and delay jitter. No physical failures were recorded by the evaluator in these runs. The control period is 20 ms, with ten 2 ms physics substeps. This is a simulation benchmark, not hardware or safety validation.

In clean HOME holds, excluding the first 50 post-step samples, EEF 6D averaged **0.724 mm** TCP error (mean of case P95s: **0.775 mm**); XYZ-only averaged **0.379 mm** (**0.421 mm**). Each covers four payloads (0, 0.5, 1, and 2 kg). Under full hardware randomization, the same EEF 6D window averaged **1.958 mm**. Across all three modes, the clean HOME tail mean improved from **1.437 to 0.799 mm** from 15k to 20k; under full randomization it moved from **2.312 to 2.079 mm**, while mean-of-case P95 was essentially unchanged (**3.448 to 3.450 mm**). These are not error bounds for moving targets. Joint error is primary for Joint 6D; orientation is a controlled objective only in EEF 6D.

- [Native case metrics](evaluation-data/e6-submm-20k-native.json) include whole-case errors and stress results in their native units.
- [Paired HOME/hold windows](evaluation-data/home-hold-e6-15k-vs-20k.csv) report TCP millimetres, inclusive one-based post-step ticks, case and sample counts, pooled P95 (`p95`), and the mean of case P95s (`mean_case_p95`). [Provenance](evaluation-data/e6-submm-hold-provenance.json) identifies the original reports and checkpoints.
- [Paired world-model metrics](evaluation-data/wm-e6-15k-vs-20k.csv) separate native displacement, open-loop error under recorded commands, and closed-loop error under reissued actor commands. These are 32-step diagnostics, not HOME target-tracking accuracy. The strict static mask requires native joint speed ≤ 0.05 rad/s and native TCP displacement ≤ 1 mm from the starting state.

The browser uses clean feedback and no added command delay. Its smoke test compares exact worker observations with the pinned ONNX export on CPU; it is not a substitute for the native benchmark. The portable CPU trainer/evaluator is a separate small reference implementation and does not recreate the E6 continuation.
